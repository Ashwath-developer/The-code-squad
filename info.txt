# PROJECT: QUICKFIRE AI
## Autonomous Multi-Agent Fire Emergency Alert and Response Coordination System

Act as a senior software architect, AI multi-agent engineer, Python developer, database engineer and UI/UX designer.

I want you to develop a complete, functional, hackathon-ready software project named **QuickFire AI**.

This project must strictly address the requirements in my uploaded hackathon problem statement titled "Multi-Agent Autonomy That Gets Real Work Done".

Do not build just a normal CRUD website or a chatbot. Build a real multi-agent application in which multiple specialized AI agents collaborate, use external tools, make decisions, execute tasks independently, communicate with each other, monitor outcomes and produce meaningful results.

The final application must be runnable on a Windows laptop without purchasing any hardware.

# 1. PROJECT OBJECTIVE

Build an intelligent fire emergency notification and coordination platform.

The system should allow an administrator to report a fire incident, specify its geographical location and choose an emergency notification radius.

The application should then use multiple AI agents to:

1. Validate and analyze the reported fire incident.
2. Identify people within the affected geographical radius.
3. Research relevant emergency information when required.
4. Prepare emergency notification messages.
5. Send or simulate SMS notifications.
6. Monitor message delivery.
7. Retry eligible failed notifications.
8. Generate a final emergency response report.

The application must have a complete working demonstration using sample data.

# 3. MULTI-AGENT ARCHITECTURE

Implement at least four specialized agents and one coordinating agent.

AGENT 1: INCIDENT ANALYSIS AGENT

Responsibilities:
- Receive fire incident reports.
- Validate latitude and longitude.
- Check whether required incident information is missing.
- Identify duplicate reports.
- Classify severity using transparent rules and AI-assisted analysis.
- Produce an incident assessment.
- Flag uncertain reports for administrator verification.

Output:
- Incident ID.
- Validation status.
- Severity classification.
- Incident summary.
- Recommended next action.

AGENT 2: LOCATION INTELLIGENCE AGENT

Responsibilities:
- Retrieve registered people's information from MySQL.
- Read their latitude and longitude.
- Calculate geographical distances using the Haversine formula.
- Identify people inside the selected radius.
- Exclude people outside the radius.
- Identify missing or invalid location information.
- Generate a geographical recipient report.
- Display affected people on an interactive map.

Output:
- Eligible recipient list.
- Excluded recipient list.
- Distance of each person.
- Selected geographical radius.
- Map information.

AGENT 3: EMERGENCY COMMUNICATION AGENT

Responsibilities:
- Receive the verified recipient list.
- Generate clear emergency notification messages.
- Use appropriate message templates.
- Send SMS using an external SMS gateway when configured.
- Use simulated SMS when real SMS credentials are unavailable.
- Track message status.
- Prevent duplicate notifications for the same incident and recipient.

Output:
- Generated message.
- Recipient number.
- Delivery status.
- Provider response or simulation result.
- Notification timestamp.

AGENT 4: MONITORING AND RECOVERY AGENT

Responsibilities:
- Monitor notification jobs.
- Check pending, successful and failed notifications.
- Retry temporary failures with a maximum configurable retry count.
- Avoid duplicate message delivery.
- Record retry attempts.
- Identify permanent failures.
- Generate a final activity report.
- Notify the administrator about incomplete operations.

Output:
- Delivery summary.
- Retry history.
- Failed message list.
- Completed task status.
- Final emergency report.

AGENT 5: AI COORDINATOR

Responsibilities:
- Receive an emergency event.
- Create an execution plan.
- Assign tasks to the appropriate agents.
- Coordinate their execution.
- Pass results between agents.
- Handle agent failures.
- Decide whether additional verification is required.
- Track overall progress.
- Store the execution history.
- Produce the final result.

The coordinator must not simply call four functions and pretend they are independent agents. Implement actual agent roles, structured inputs and outputs, coordination and recorded task execution.

# 4. AUTONOMOUS DECISION-MAKING

The application must demonstrate meaningful autonomous decisions.

Examples:

- If coordinates are invalid, request correction instead of continuing.
- If an incident report is incomplete, ask for missing information.
- If a report appears duplicated, flag it for review.
- If a person is outside the selected radius, exclude them.
- If a notification fails temporarily, schedule a retry.
- If a recipient has invalid information, flag that record.
- If an AI agent fails, record the failure and execute an appropriate recovery path.
- If an incident has not been verified, do not send real emergency SMS.

Use human approval before actual external emergency notifications.

Maintain an audit trail explaining why each decision was made.
